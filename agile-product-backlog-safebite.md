# SafeBite — Product Backlog

**Project:** SafeBite  
**Project Type:** Entrepreneurial Work-Integrated Learning (WIL)  
**Development Approach:** Agile

## 1. Purpose

The product backlog contains the features, improvements and development tasks identified for SafeBite. Items are prioritised according to their importance to users and the project's objectives.

The backlog is intended to guide planning and help the team decide which work should be completed first. Priorities and statuses must be reviewed with the team.

## 3. Priority Definitions

**High:** Core functionality that directly supports the main food safety, health profile or inventory objectives.

**Medium:** Additional functionality that improves convenience, accessibility, personalisation or the overall user experience.

These priorities are proposed for planning and should be agreed upon by the project team.

## 4. Product Backlog Management

The team should review the backlog regularly and update it as requirements change.

- Add new items when additional requirements are identified.
- Reprioritise items according to user needs and project constraints.
- Break large features into smaller, manageable tasks.
- Link backlog items to relevant user stories and acceptance criteria.
- Update statuses based on actual development progress.
- Remove or revise items only when the team agrees that a change is appropriate.

## 5. Definition of Done

A backlog item may be marked complete when its agreed acceptance criteria have been met, the required functionality has been implemented, relevant testing has been performed and any necessary documentation has been updated.

## 6. Reflection

Creating a product backlog helps organise a large application into manageable pieces of work. It supports decision-making by helping the team prioritise important features and plan development activities. For SafeBite, the backlog also helps maintain a connection between user needs, the application's food safety objectives and the team's development work.
