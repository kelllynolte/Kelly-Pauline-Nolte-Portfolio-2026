## 3. Challenges and Solutions

### Challenge 1: Understanding the Integration

**Challenge:** Understanding how BeeHive action items should be transferred into Purple Bee tasks while respecting the requirements of both applications.

**How I addressed it:** I used the available project requirements and researched the roles of both systems to understand the expected integration workflow.

**Outcome:** This helped me organise the integration requirements and identify the information needed to create a task correctly.

**What I learned:** Researching the existing systems and reviewing requirements are important first steps when working on an integration project.

### Challenge 2: Documenting Technical Requirements

**Challenge:** Breaking the integration requirements into clear, manageable tasks and documenting expected system behaviour.

**How I addressed it:** I organised the requirements into sections covering validation, permissions, API communication, task creation, duplicate prevention, and error handling.

**Outcome:** The requirements could be represented more clearly through user stories, backlog items, and sprint tasks.

**What I learned:** Good documentation helps a development team understand the expected functionality and provides a basis for implementation and testing.

### Challenge 3: Planning the Integration Work

**Challenge:** Identifying the main tasks and dependencies involved in connecting two applications.

**How I addressed it:** I used Agile planning artefacts to organise the proposed work and identify the features that need to be prioritised.

**Outcome:** The proposed backlog and sprint plan provide a structure that can be reviewed and updated with the project team.

**What I learned:** Agile planning supports teamwork, prioritisation, progress tracking, and early identification of dependencies.
